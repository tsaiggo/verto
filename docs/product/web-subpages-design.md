# Verto Web: Mail、阅读器与子页面设计规格（草案）

状态：待评审 · 2026-09-27

范围：桌面 Web；沿用当前 Workspace 侧栏、主题与最右侧 Agent。移动端不在本轮设计范围内。

基线：`main`（已包含 PR #209 的统一侧栏）；本文件描述目标体验，不表示功能已实现。

## 1. 目标与现状

用户应能在同一工作台完成三条连续流程：读邮件并选择性保存有价值的信息；导入和阅读 EPUB/PDF 并留下可回跳的笔记；把笔记整理为有父子层级、链接和反向链接的页面。一级导航保持稳定，内容区随任务变化，Agent 对话在普通页面切换间保留。

| 区域 | 当前可用能力 | 设计必须补齐的部分 |
| --- | --- | --- |
| Mail | Gmail/Outlook 单账号只读连接、文件夹、分页列表和纯文本正文；`?folder`/`?message` 可定位 | 连接与过期状态、明确的错误恢复、窄桌面列表/详情、显式保存与 Agent 引用 |
| EPUB | Node 命令行将章节转为 MDX；现有 MDX 阅读器可阅读转换结果 | 浏览器导入、保留原件、书籍目录/整书进度、章节标注 |
| PDF | 尚无 Web 导入与阅读链路 | 导入、渲染、页码/缩放、文本层、按页引用与无文本 PDF 状态 |
| 子页面 | Web 内容树按文件夹生成；Web 编辑器把 MDX 下载到本机 | 可写入的页面库、稳定 ID/父子关系、保存反馈、移动与链接/反向链接 |
| Agent | 普通 Workspace 路由有常驻面板 | `/read` 和 `/editor` 仍使用各自助手；需统一显式来源和引用 |

证据入口：`components/shell/UnifiedSidebarPanel.tsx`、`components/mail/MailWorkspace.tsx`、`lib/epub/import.ts`、`components/layout/AppShellClient.tsx`、`app/editor/EditorClient.tsx`、`docs/product/web-workspace-roadmap.md`。

## 2. 共同页面框架

现有 Web 框架是 56px 图标轨道 + 232px Workspace 面板 + 主工作区 + 最右 Agent。保持 `--verto-*` 主题 token、边框、焦点样式、行高度和选中态；不要在三个页面分别实现新侧栏。用户可折叠 Workspace 面板和 Agent，选择在页面切换间保留。

| 位置 | Mail | EPUB/PDF | 页面与笔记 |
| --- | --- | --- | --- |
| 全局导航 | Mail 入口 | Library 入口 | Library → Notes 入口 |
| Workspace 上下文面板 | 账号身份、文件夹、未读数 | 当前书/文档目录、章节或页面缩略图入口 | 页面树、最近页面、收藏 |
| 主工作区 | 消息列表与正文 | 阅读画布、格式对应工具条 | 面包屑、标题、正文、子页面 |
| 最右 Agent | 对话保留；邮件仅在用户选择后附加 | 显示已附加的书/章节/页范围 | 显示已附加的当前页面或选区 |

### 信息架构与路由

| 路由 | 身份 | 说明 |
| --- | --- | --- |
| `/mail?folder=…&message=…` | 已有 | URL 承载文件夹和邮件；恢复连接后才尝试重新打开，失效时显示恢复路径 |
| `/mail?account=…&folder=…&message=…` | 建议 | 用不含邮箱地址的账号身份绑定深链接，避免自动恢复另一提供商后误打开旧 message ID |
| `/library?type=book|pdf|document` | 建议 | Library 中按类型筛选；导入入口始终可见 |
| `/library/items/[itemId]` | 建议 | 由稳定 ID 打开 EPUB/PDF；旧 `/read/*` 的 MDX 链接先兼容 |
| `/library?view=notes` | 已有 | 页面库索引；从这里进入页面树 |
| `/library/pages/[pageId]` | 建议 | 页面 URL 与标题、文件名、父节点无关；移动/改名不换 URL |

在 1280px 桌面视口且 Agent 打开时，主区可能不足以同时显示列表、详情和内部 Inspector。Mail 按主容器宽度切成「列表」或「详情」单视图；阅读器把目录放在 Workspace 面板，笔记/信息以主区内抽屉打开，不再固定增加一列。Agent 折叠后可以恢复较宽的双栏布局。设计验收至少检查 1280px 与 1440px、Agent 开/关、浅色/深色。

### 关键流程

1. **邮件到页面**：连接账号 → 选择文件夹与邮件 → 选中摘录或选择整封 → 预览保存范围与来源 → 确认保存到个人页面库 → 页面显示原邮件引用。断开邮箱后保存的内容仍可读，原邮件回跳则要求重新连接。
2. **阅读到页面**：导入 EPUB/PDF → Library 中打开 → 恢复章节/页与位置 → 选区高亮或写笔记 → 选择父页面保存 → 在笔记中点击引用返回原章节/页。没有文本层的 PDF 只支持页级笔记。
3. **页面整理**：创建页面/子页面 → 编辑并看到保存状态 → `[[` 选择目标页 → 移动页面 → URL、链接、反向链接及来源笔记仍指向原 ID。导出再导入后保持这些关系。

### 共同数据与引用契约

- **内容身份**：每个导入文档、书、邮件保存项和页面拥有稳定 ID。路径、标题和文件名是可变属性，不能作为笔记、书签、进度或 Agent 引用的主键。
- **来源引用**：使用按格式区分的 `SourceRef`，而非任意 URL。邮件为 `{ kind: "mail", provider, accountId, messageId, excerpt? }`；EPUB 为 `{ kind: "epub", itemId, revisionHash, spineHref, cfi? / textQuote+context? }`；PDF 为 `{ kind: "pdf", itemId, revisionHash, pageIndex, textQuote+offset/rect? }`；页面为 `{ kind: "page", vaultId, pageId, blockId? }`。PDF 内部 `pageIndex` 从 0 开始，界面页码从 1 开始。文件版本改变时，引用卡片说明版本不符；精确位置失败时降级到同章节/同页；原件缺失时保留来源身份但不能假装回跳成功。
- **阅读位置**：进度与标注分开存。MDX 用标题/文本位置；EPUB 用 spine 章节和字体/重排后仍可恢复的章内位置；PDF 用页索引、页内相对位置、适宽/适页模式与缩放。PDF 旋转或缩放后重新计算文本选区位置。
- **Agent 边界**：当前打开不等于已授权读取。面板显示已附加来源、版本与范围；「就此提问」可先预填附件，用户能移除。翻页/切章不自动扩大已附加范围，用户可明确改为「当前文档」。实现必须在检索和工具调用层按允许的 item ID/范围过滤，并记录每次回答使用的来源快照；仅增加 UI 附件 chip 不足够。当前 `loadAgentSources()` 会默认装载可读 MDX，迁移时需要一并收紧。邮件内容不因连接邮箱而自动进入 Library、搜索索引或 Agent 上下文。
- **跨页面动作**：从选区创建笔记、从邮件显式保存、从 Agent 回答保存页面时，保留 `SourceRef`，点击引用能返回原邮件、章节或 PDF 页。

## 3. Mail 子页面

### 页面布局与交互

上下文面板顶部显示当前账号、提供商和连接状态，下面显示 Inbox、Sent、Drafts、Archive/Trash（以提供商实际能力为准）与自定义文件夹；长名称截断并在悬停/键盘聚焦时显示全名。主区标题显示文件夹名、刷新与消息数量；列表行展示发件人、主题、摘要、日期、未读状态及附件**存在标记**（首轮不含附件下载/预览）。选中邮件后显示主题、发/收件人、时间、纯文本正文与返回列表。基础体验保持只读。搜索与显式保存到本地 Library 可在现有读取权限下分别设计；撰写/发送、归档和删除才进入新增 OAuth 权限阶段。

| 状态 | 用户看到什么 | 可执行动作 |
| --- | --- | --- |
| 未配置 OAuth | 工作区部署尚未配置 Gmail/Outlook 的说明，与用户未授权明确区分 | 查看 README 的 Web Mail 部署文档；普通用户无法在产品内自助配置 client ID |
| 已配置未连接 | Gmail/Outlook 连接按钮及只读权限说明 | 选择提供商连接 |
| OAuth 连接/恢复中 | 原位进度、按钮禁用，页面结构保持稳定；Outlook redirect 返回后继续显示恢复状态 | 等待；仅对确实可取消的步骤提供取消 |
| OAuth 拒绝/脚本或 redirect 失败 | 解释用户取消、授权拒绝或技术失败的区别 | 重试或选另一提供商 |
| 已连接、有邮件 | 文件夹、列表、正文或选择提示 | 切换、刷新、分页、打开邮件 |
| 空文件夹 | 单独的空态，只在请求成功且结果为空时出现 | 刷新或切换文件夹 |
| 列表/正文加载失败 | 对应区域显示错误与重试；不同时宣称文件夹为空 | 重试、返回列表 |
| 401 授权过期 / 403 权限撤销 | 区分需要重新登录与缺少授权；保留所在文件夹位置 | 重新连接、重新授权或断开 |
| 断开中/断开失败 | 状态与连接中区分；失败不假装已安全断开 | 重试断开、返回邮箱 |
| 深链接失效/账号切换 | 邮件被删除/移动、权限失效或当前账号与链接不匹配时，显示原账号和失败原因 | 切回原账号、重连或返回当前账号 Inbox |

列表和详情使用 URL 选中状态。在窄主区打开邮件后显示详情与「返回文件夹」；浏览器 Back 返回列表。Gmail 令牌只在内存中，刷新后需要重新连接；Outlook 仅可在浏览器 session 内恢复。恢复成功且账号匹配时尝试打开原邮件，失败则显示深链接失效态。两家都配置时，不得因为优先恢复另一家而把旧 message ID 当作该账号邮件读取。切换文件夹清除旧正文和旧错误；分页失败保留已加载行。未读不能只靠字重区分。未配置 OAuth 的预览环境仅能审查未配置态；真实 Gmail/Outlook 登录和已连接视觉稿需要可用的测试账号再验证。

### Mail 首轮验收

1. 在 1280px/1440px Web 视口和 Agent 开/关两种状态下，可以从文件夹进入邮件并回到原列表，URL 与选中态一致。
2. 成功空列表、网络失败、权限过期有不同文案和恢复动作；失败时不出现「No messages」。
3. 连接邮箱后，Agent 附件列表不自动增加邮件；这一边界由检索层验证，不以视觉 chip 代替。

显式保存/附加属于后续跨内容切片：保存前预览整封或摘录及目标页面，确认后保存项可离线阅读；回跳远端邮件如需重新授权须明确提示。该动作不要求扩大现有只读 OAuth scope，其验收与基础邮箱体验分开。

## 4. EPUB/PDF 阅读子页面

### 导入与 Library

Library 提供 Import 按钮，支持本地 EPUB/PDF。流程：选文件 → 校验类型/大小/解析 → 保留原件与元数据 → 生成稳定 item ID → 出现在 Library → 打开并恢复阅读位置。首版草案使用独立的浏览器本地 Blob store 与元数据索引；现有 `browser-local-folder.ts` 的 MDX 读缓存会清空自身文件 store，不能直接复用为书库。导入不得只生成一次性 MDX 然后丢弃原件。重复导入以文件指纹提示「打开现有项」或「另存一份」；同名但内容变更属于新修订，不能暗中覆盖标注。文件过大、解压上限、浏览器配额/隐私模式限制、用户取消都要给出明确且可恢复的结果。

### 阅读画布

| 控件/行为 | EPUB | PDF |
| --- | --- | --- |
| 导航 | 书籍目录、上一/下一章、章内位置、整书进度、内部链接/脚注回跳 | 页码输入、上一/下一页、缩略图入口、总页数 |
| 显示 | 可重排文字、字体/行距/宽度设置、图片 | 适宽/适页/缩放、保留原版式、文本层 |
| 选区 | 高亮、写笔记、就此提问；锚点包含书与章 | 文本层选区同上；引用包含页码与文本范围 |
| 恢复 | 上次章节与章内位置 | 上次页码、页内位置与显示模式；必要时退回页首 |
| 来源 | 书名、作者、原 EPUB | 文件名、页码、原 PDF |

Reader 顶部保持「返回 Library」、标题、来源和格式工具条。Workspace 面板显示目录；主画布保证阅读宽度。笔记/高亮从主区右缘以抽屉展开，不替代阅读画布；打开时保留选区、章节/页和滚动位置，关闭后焦点回到原阅读位置。最右 Agent 维持同一会话，引用可跳回本章/本页。现有 `/read` 和 `/editor` 会屏蔽全局 Agent，实施时需迁移其上下文与写入预览/确认行为，不能让两个 Agent 会话同时出现。大型 PDF 按页懒渲染、虚拟化缩略图并取消离屏渲染任务。

| 异常/空态 | 行为 |
| --- | --- |
| 导入中、用户取消或解析失败 | 显示文件名、进度阶段与可重试错误；取消/失败不留下半成品 Library 项 |
| EPUB 无目录/缺图片/无可读章 | 有可读章时生成最小目录并标出受影响章节；零可读章时阻止入库 |
| EPUB 不支持的内容 | 首版采用重排/规范化阅读；fixed-layout、DRM/加密及多媒体无法处理时明确说明，不伪装成完整还原 |
| PDF 无文本层 | 仍可按页阅读、写页级笔记和页级引用；选区高亮和基于正文的 Agent 摘要/问答不可用，提示当前版本不支持 OCR |
| PDF 需密码/密码错误/损坏 | 分别显示状态；若首版支持解密则临时输入密码且不持久化，否则说明不支持并允许重选 |
| 原件 Blob 缺失但索引仍在 | 保留元数据并允许重新关联；指纹不符时要求用户决定是否作为新修订 |
| 浏览器站点数据被清除 | 本地索引和原件都可能消失，只能从先前导出的备份恢复或重新导入 |
| 引用目标加载中/位置失效 | 先显示定位进度；失败时回到相应章节或页，引用卡片标出精确选区无法定位或文件版本不符 |

### 阅读器首轮验收

1. 导入后刷新页面仍能在同一浏览器打开原 EPUB/PDF，并恢复到上次章节/页及可用的章内/页内位置；配额失败不能出现幽灵 Library 项。
2. 一条 EPUB 笔记能回到正确章节；一条 PDF 笔记能回到正确页。有文本层时尽可能定位选区。
3. 从 Agent 引用点击返回原件；检索层证明未显式附加的其他私人文件不进入本次回答来源，回答保存本次来源快照。
4. 打开笔记抽屉并保存后，阅读选区、滚动位置和焦点可恢复；大 PDF 的首屏不必等待所有页面渲染。

## 5. 类 Notion 子页面

这里的「类 Notion」指页面树、子页面、链接与页面内整理体验；首轮保持个人、文件可迁移的 Verto 知识库定位。

### 页面结构与动作

Notes 入口打开页面索引。Workspace 上下文面板分为可写的 **My Pages** 与只读的 **Connected Sources** 两个根；跨根拖动禁止，只读项只可「引用到我的页面/另存为笔记」。My Pages 显示可展开的页面树，选中页面自动展开祖先，树行提供「新建子页面」与更多操作。主区依次显示父链面包屑、页面图标/标题、正文、子页面列表和关联信息。空页提示可开始写作或创建子页面；只读来源不显示无法执行的 Add subpage。

| 动作 | 交互结果 | 失败与恢复 |
| --- | --- | --- |
| 新建根页/子页 | 先以 `pending` 出现在树与正文，生成稳定 page ID；提交成功转为 `committed` | 失败节点标记 `failed`，正文草稿保留在恢复区，提供重试/导出；不伪装为已保存 |
| 改名 | 树、面包屑、搜索同步更新；URL 和引用不变 | 显示保存错误并保留输入 |
| 移动/排序 | 选择目标父页或拖放；阻止把页移入自身后代；父子关系与兄弟顺序作为一次事务提交 | 失败回滚树位置并说明原因 |
| 删除 | 显示受影响的子树页面数，整棵子树进入回收站 | 恢复原父级；原父级不在时提示改放根页；链接显示目标在回收站 |
| 页面链接 | `[[` 搜索并插入链接；可从来源选区创建带引用的笔记 | 未解析或重名链接显示选择目标 |
| 反向链接 | 页底/信息视图列出引用当前页的来源 | 索引更新中显示状态，不静默遗漏 |

页面模型至少包含全局唯一 `pageId`、`vaultId`、`parentPageId`、`sortOrder`、`title`、`body`、`revision` 与时间戳。URL 用全局 page ID 定位；`vaultId` 区分备份与未来多库。现有 Desktop `verto_id` 可作为兼容入口；已有 MDX、GitHub/OneDrive 只读内容按目录投影到 Connected Sources，不自动改写原文件。页面正文里的链接以目标 page ID 存在结构化内容中；输入 `[[` 时显示标题搜索和重名消歧，渲染时展示标题，目标删除/缺失时显示断链。

**本草案的 v1 写入权属：浏览器本地库。** My Pages 的正文、树、链接索引与修订版本由当前浏览器 IndexedDB 持有；当前 Web `ContentSource` 和文件夹导入仍是只读来源，不充当写入后端。局域网里从另一台设备打开 Verto，不会看到这些页面；界面必须说明这一点并提供备份/导出入口。存储配额不足、浏览器禁用存储或站点数据清除分别给出错误与恢复路径。若用户要求跨设备共享，需把本节改为工作区服务端写入、权限与并发规格，再开始实现。

**可迁移格式**：导出一个含 `manifest.json` 和 MDX 文件的包。清单记录 `vaultId/pageId/parentPageId/sortOrder/revision` 与文件路径；每个 MDX frontmatter 也包含 `verto_id`、父 ID 和顺序。内部按目标 ID 存的页面链接在导出时生成相对 Markdown 链接，导入时以清单解析回 ID；重名标题不能成为链接主键。验收必须执行「导出 → 清空本地库 → 导入」，验证页面树、链接、反链、来源引用和页面 ID 保持一致。

**旧数据迁移**：先为可写旧文档读取或分配稳定 ID，并建立 `{旧 href/docSlug → 新 ID}` alias 表；读取旧书签、集合、进度和标注时双读旧键与新 ID，新写入只用 ID；确认迁移后再逐步去掉旧键。重复 ID、路径冲突和只读外部来源必须进入显式处理态，不能静默改写用户文件。用现有数据样本验证移动/改名后书签、标注和进度仍可回跳。

保存状态必须可见：`dirty → saving → saved`，失败显示 `error` 并保留草稿。写入按页面 revision 做比较；同一浏览器多标签发生版本冲突时显示当前草稿与已存版本，提供复制/导出或人工选择，不能自动覆盖。离开未保存页面需明确处理；键盘可操作树的展开、选中、菜单和新建，操作结束焦点返回合理位置。

### 子页面首轮验收

1. 创建子页后，树、面包屑、URL、正文一致；刷新后仍存在。失败的 pending 页显示草稿恢复，不计为已保存。
2. 移动/改名后，页面链接、书签、进度和来源笔记仍指向同一 page ID；循环移动被拒绝，整棵子树可删除并恢复。
3. 重名子页、重名 `[[` 搜索结果、断链、存储失败和双标签版本冲突均有可恢复状态；页面树支持键盘操作与自动展开祖先。
4. 导出、清空并重新导入后，层级、顺序、链接、反链和 ID 保持一致；在 1280/1440px、Agent 开/关、浅/深主题下可完成编辑流程。

## 6. 设计与实现切片

| 顺序 | 可 review 产物 | 前置与验收重点 |
| --- | --- | --- |
| 1. 视觉与流程评审 | 三类页面在 1440/1280、浅/深主题、Agent 开/关下的关键页面稿；逐状态交互稿 | 复用现有 sidebar/token，确认 Web 保存位置 |
| 2. 共享契约 | 稳定 item/page ID、分格式 locator、SourceRef、读写能力声明、迁移方案 | 改名/移动/重导入不破坏已有关系 |
| 3. Mail 基础体验 | 连接与错误恢复、列表/详情、窄主区行为 | 保持只读权限；已连接流程用测试账号验证 |
| 4. EPUB/PDF 导入和阅读 | 本地导入、原件保存、格式专用导航与进度 | 刷新恢复、无文本/损坏状态、章节/页引用 |
| 5. 页面树与链接 | 可写页面库、子页操作、正文保存、链接/反链 | 写入失败可恢复，导出可迁移 |
| 6. 跨内容动作 | 显式保存邮件/选区为页面，Agent 附件与引用回跳 | 私人来源不自动进入索引或 Agent；写入需预览确认 |

每个切片都保留既有 MDX 阅读与静态构建能力。Mail 的撰写、发送、归档和删除涉及另一组 OAuth 权限与交互，另起设计评审。PDF OCR、协作编辑与跨设备同步也不属于首轮验收。

## 7. 评审时需确认

1. 本草案采用浏览器本地库作为 v1 写入位置。请确认是否接受每台浏览器各自保存；若必须局域网跨设备共享，需改成服务端写入方案。只读文件库投影无法满足可创建子页面的目标。
2. 设计稿先优先验证「阅读 → 摘录 → 子页面整理」闭环，还是「Mail → 显式保存 → 页面整理」闭环；两条都在本规格内。
3. 邮件保存到知识库时的默认粒度：整封邮件或用户选中的摘录。建议默认摘录，保留回跳到原邮件的引用。

## 8. 可视化预览

本分支提供 `/labs/web-subpages` 预览路由，直接复用现有 `WorkspaceShell`、主题切换和侧栏尺寸。页面顶部可切换 Mail、EPUB/PDF、Subpages，选择 1280px、1440px 或流动宽度，并折叠/展开右侧 Agent。

- Mail：用五封示例邮件检查列表、详情和窄主区的返回流程；不连接真实邮箱，也不发送或修改邮件。
- EPUB/PDF：切换格式、章节/页、文字大小或缩放；打开笔记抽屉，并检查 PDF 无文本层状态。示例内容不是文件解析结果。
- Subpages：切换父/子页，编辑标题与正文，新增和改名示例子页；左侧树同步更新。所有编辑只保存在当前预览组件内，刷新即重置。
- Agent：可显式附加/移除当前示例来源，跨三个预览面保持附件；对话发送在预览中禁用。真正的检索范围限制仍以第 2 节的实现契约为准。

该路由用于评审结构与交互，不代表 Mail OAuth、文件导入、持久化页面库、真实 Agent 调用或本文列出的错误恢复状态已经实现。验收这些能力仍须按照第 6 节逐切片完成。
